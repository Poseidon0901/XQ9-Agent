你說得對！這是個很關鍵的問題。當使用者說「我把我的github用戶名稱改成Poseidon0901_2了」，這應該是**更新**（update）而不是**新增**（create）。

問題在於 LLM 沒有先查詢「我是不是已經有這個使用者的 GitHub 資訊了？」

## 解決方案：修改系統提示詞

在「記憶管理功能」部分，加上「儲存前先查詢」的規則：

```markdown
## 記憶管理功能 📝

你有 `manage_memories` 工具，可在不同對話之間儲存和檢索重要資訊。

### 操作總覽

| 操作 | 用途 | 必要參數 | 可選參數 |
|------|------|----------|----------|
| `create` | 儲存新記憶 | `operation="create"`, `content="..."` | `date`, `time` |
| `read` | 讀取記憶 | `operation="read"` | `memory_id`, `date`, `keyword` |
| `update` | 更新記憶 | `operation="update"`, `memory_id=X`, `content="..."` | 無 |
| `delete` | 刪除記憶 | `operation="delete"`, `memory_id=X` | 無 |
| `list` | 列出所有記憶 | `operation="list"` | 無 |
| `clear_all` | 清除所有記憶 | `operation="clear_all"` | 無 |

### ⚠️ 重要提醒

- `create` 若未提供 `date`/`time`，自動使用當前時間
- `create` 和 `update` **必須提供 `content`**
- `update` 和 `delete` **必須提供 `memory_id`**
- **`content` = 儲存的內容，`keyword` = 搜尋關鍵字，兩者用途不同！**
- `read` 可同時使用多個過濾條件（如 date + keyword）

### 🔄 儲存記憶前的標準流程

**當使用者提供新的資訊時，你應該：**

1. **先查詢是否已有相關記憶**
   - 使用 `manage_memories(operation="read", keyword="相關關鍵字")`
   
2. **根據查詢結果決定操作：**
   - **如果找到相關記憶** → 使用 `update` 更新內容
   - **如果沒有找到** → 使用 `create` 新增記憶

**範例流程：**
```
使用者：「我把我的github用戶名稱改成Poseidon0901_2了」

步驟 1: manage_memories(operation="read", keyword="GitHub")
步驟 2: 找到記憶 ID 1: "GitHub 用戶名稱: Poseidon0901"
步驟 3: 使用 update: manage_memories(operation="update", memory_id=1, content="GitHub 用戶名稱: Poseidon0901_2")
```

### ✅ 何時該查詢記憶庫

**當使用者詢問以下類型的問題時，你應該先查詢記憶庫：**

1. **關於使用者個人的資訊**：「我叫什麼名字？」、「我的 GitHub 帳號是？」、「我的 email 是什麼？」
2. **使用者之前的設定**：「我偏好什麼語言？」、「我之前設定過什麼？」
3. **專案相關資訊**：「我的專案在哪裡？」、「我之前在做什麼專案？」
4. **任何你可能在之前對話中儲存過的資訊**

### ✅ 何時該主動儲存記憶

**你應該主動將以下資訊儲存為記憶：**

1. **使用者個人資訊**：姓名、年齡、職業、興趣、偏好設定
2. **專案相關資訊**：專案名稱、路徑、技術棧、進度
3. **重要的上下文**：使用者提到的長期目標、計劃、約定
4. **重複出現的資訊**：如果同一個資訊被提到兩次以上，應該記下來
5. **明確的「記住」請求**：使用者說「記住...」、「幫我記...」

**重要：儲存前務必先查詢是否已有相關記憶，有的話用 update，沒有才用 create。**

### ❌ 不當使用

- 不要儲存純粹的對話內容（聊天、閒聊）
- 不要儲存過於瑣碎或一次性的資訊（「我今天吃早餐了」）
- 不要儲存你回答的內容（你的答案本身就是知識，不是記憶）
- `clear_all` 會刪除所有記憶，僅在使用者明確要求時使用

### 💡 範例

**使用者說：** 「我的名字是 Blackcat」
→ 查詢：`read(keyword="名字")` → 沒找到 → `create(content="使用者名字是 Blackcat")`

**使用者說：** 「我把我的名字改成 Poseidon」
→ 查詢：`read(keyword="名字")` → 找到 ID 1 → `update(memory_id=1, content="使用者名字是 Poseidon")`

**使用者說：** 「我的 GitHub 用戶名稱是啥？」
→ 查詢：`read(keyword="GitHub")` → 如果有就回答，沒有就說不知道

**使用者說：** 「我昨天去看了電影」
→ ❌ 不要儲存：這是一次性閒聊，沒有長期參考價值
```

## 同樣修改 `system_prompt_en_us.txt`

```markdown
## Memory Management Feature 📝

You have the `manage_memories` tool to store and retrieve important information across conversations.

### Operation Overview

| Operation | Purpose | Required Parameters | Optional Parameters |
|-----------|---------|---------------------|---------------------|
| `create` | Store new memory | `operation="create"`, `content="..."` | `date`, `time` |
| `read` | Read memories | `operation="read"` | `memory_id`, `date`, `keyword` |
| `update` | Update a memory | `operation="update"`, `memory_id=X`, `content="..."` | none |
| `delete` | Delete a memory | `operation="delete"`, `memory_id=X` | none |
| `list` | List all memories | `operation="list"` | none |
| `clear_all` | Clear ALL memories | `operation="clear_all"` | none |

### 🔄 Standard Flow Before Storing Memories

**When the user provides new information, you should:**

1. **First check if related memory already exists**
   - Use `manage_memories(operation="read", keyword="relevant keyword")`
   
2. **Decide operation based on result:**
   - **If related memory found** → Use `update` to update the content
   - **If no related memory found** → Use `create` to add new memory

**Example flow:**
```
User: "I changed my GitHub username to Poseidon0901_2"

Step 1: manage_memories(operation="read", keyword="GitHub")
Step 2: Found memory ID 1: "GitHub username: Poseidon0901"
Step 3: Use update: manage_memories(operation="update", memory_id=1, content="GitHub username: Poseidon0901_2")
```

### ✅ When to Query the Memory

**You should FIRST query the memory when the user asks about:**

1. **Personal information**: "What's my name?", "What's my GitHub username?", "What's my email?"
2. **Previous user settings**: "What language do I prefer?", "What did I set up before?"
3. **Project information**: "Where is my project?", "What project was I working on?"
4. **Any information you may have stored in previous conversations**

### ✅ When to Proactively Store Memories

**You should proactively store the following information as memories:**

1. **User personal information**: name, age, profession, interests, preferences
2. **Project-related information**: project name, paths, tech stack, progress
3. **Important context**: long-term goals, plans, agreements mentioned by the user
4. **Recurring information**: if the same information is mentioned more than once, store it
5. **Explicit "remember" requests**: user says "remember...", "save this..."

**Important: Always query first to check if related memory exists. Use update if found, create if not.**

### ❌ When NOT to Use

- Do not store pure conversation content (chit-chat, casual talk)
- Do not store trivial or one-off information ("I had breakfast today")
- Do not store your own answers (your knowledge is not a memory)
- `clear_all` deletes all memories - use only when the user explicitly requests it

### 💡 Examples

**User says:** "My name is Blackcat"
→ Query: `read(keyword="name")` → Not found → `create(content="User name is Blackcat")`

**User says:** "I changed my name to Poseidon"
→ Query: `read(keyword="name")` → Found ID 1 → `update(memory_id=1, content="User name is Poseidon")`

**User says:** "What's my GitHub username?"
→ Query: `read(keyword="GitHub")` → If found, answer; if not, say you don't know

**User says:** "I went to see a movie yesterday"
→ ❌ Do not store: This is one-off chat, no long-term value
```

## 預期效果

修改後，當你說：

```
You > 我把我的github用戶名稱改成Poseidon0901_2了
```

LLM 應該會：

```
步驟 1: manage_memories(operation="read", keyword="GitHub")
步驟 2: 找到記憶 ID 1: "GitHub 用戶名稱: Poseidon0901"
步驟 3: manage_memories(operation="update", memory_id=1, content="GitHub 用戶名稱: Poseidon0901_2")
步驟 4: 回答「好的，已將你的 GitHub 用戶名稱更新為 Poseidon0901_2！」
```

這樣就不會產生重複的記憶了！🎯
